Storing passwords, password_hash and password_verify

Never store a password as it was typed, and never store it with md5 or sha1. When a database is stolen, plain passwords are read at once and those quick hashes are cracked fast, and people reuse passwords on other sites.

PHP has the right tool built in.

$hash = password_hash($password, PASSWORD_ARGON2ID);

Store $hash in a column of type VARCHAR(255), so there is room for longer hashes later. The result already contains a random salt and the settings, so you store nothing else. AI-2's PHP has Argon2id. Where it is missing, PASSWORD_DEFAULT gives bcrypt.

To check a login, read the hash for that user and compare.

if ($user && password_verify($password, $user['password_hash'])) {
    session_regenerate_id(true);
    $_SESSION['user_id'] = $user['id'];
}

When no user was found, still run password_verify against a fixed dummy hash made the same way, so the answer takes the same time either way and its speed does not tell strangers which accounts exist. Give the same message, wrong email or password, in both cases, and slow down repeated failed attempts.

After a successful login, password_needs_rehash($user['password_hash'], PASSWORD_ARGON2ID) says whether to store a new password_hash, so old bcrypt hashes move to Argon2id. password_verify reads both.

bcrypt uses only the first 72 bytes of a password and silently ignores the rest. Argon2id has no such limit. Do not shorten passwords yourself and do not set a maximum length below 64 characters. If you must use bcrypt, refuse a password with strlen($password) > 72 instead of letting it be cut.

For password reset links, make the token with bin2hex(random_bytes(32)), never rand or uniqid, store only a hash of it, let it expire within an hour, and delete it as soon as it is used.
