Storing passwords, password_hash and password_verify

Never store a password as it was typed, and never store it with md5 or sha1. When a database is stolen, plain passwords are read at once and those quick hashes are cracked in minutes, and people reuse passwords on other sites.

PHP has the right tool built in.

$hash = password_hash($password, PASSWORD_DEFAULT);

Store $hash in a column of type VARCHAR(255). The result already contains a random salt and the settings, so you store nothing else. PASSWORD_DEFAULT is bcrypt today and may become a stronger method in a later PHP, which is why the column needs room to grow.

To check a login, read the hash for that user and compare.

if ($user && password_verify($password, $user['password_hash'])) {
    session_regenerate_id(true);
    $_SESSION['user_id'] = $user['id'];
}

After a successful login, ask whether the stored hash should be updated, so old hashes move to the current method.

if (password_needs_rehash($user['password_hash'], PASSWORD_DEFAULT)) { ...store password_hash($password, PASSWORD_DEFAULT)... }

Give the same message, wrong email or password, whether the email exists or not, so the form does not tell strangers which accounts exist. Slow down repeated failed attempts from the same address or account.

bcrypt uses only the first 72 bytes of a password, so a very long password is cut there. Do not shorten passwords yourself and do not ask for a maximum length below 64 characters.

For tokens such as password reset links, use bin2hex(random_bytes(32)), never rand or uniqid, and store only a hash of the token.
