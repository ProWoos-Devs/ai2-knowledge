Showing user input on a page safely, htmlspecialchars

Anything a visitor typed, and anything read from a database that a visitor once typed, must be escaped before it is printed into HTML. Without that, a name such as <script>...</script> runs as code in the browser of everyone who views the page. This is called cross-site scripting, XSS, and it can steal logins.

Escape at the moment of printing.

echo htmlspecialchars($name, ENT_QUOTES, 'UTF-8');

It turns < > & " and ' into harmless entities, so the browser shows the characters instead of obeying them. ENT_QUOTES and UTF-8 are already the defaults in PHP 8.1 and later, but writing them keeps the code safe on older versions too. A short helper saves typing.

function e(string $s): string { return htmlspecialchars($s, ENT_QUOTES, 'UTF-8'); }

The same escaping protects attribute values, <input value="<?= e($email) ?>">, as long as the value is inside quotes.

It is not enough in other places. Inside JavaScript, use json_encode($value, JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT). Inside a URL, use urlencode for each part. A link address typed by a visitor must also be checked to start with http:// or https://, because javascript: addresses run code when clicked.

strip_tags is not a security function. Use htmlspecialchars.

Escape for HTML only when printing. Store the original text in the database, so it can still be used correctly elsewhere.
