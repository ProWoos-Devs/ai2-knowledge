Showing user input on a page safely, htmlspecialchars

Anything a visitor typed, and anything read from a database that a visitor once typed, must be escaped before it is printed into HTML. Without that, a name such as <script>...</script> runs as code in the browser of everyone who views the page. This is called cross-site scripting, XSS, and it can steal logins.

Escape at the moment of printing.

echo htmlspecialchars($name, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');

It turns < > & " and ' into harmless entities, so the browser shows the characters instead of obeying them. ENT_SUBSTITUTE keeps text that holds one broken character, which would otherwise come back as an empty string. These are already the defaults in PHP 8.1 and later, but writing them keeps the code safe on older versions too. A short helper saves typing, and accepts a NULL column without stopping the page.

function e(?string $s): string { return htmlspecialchars($s ?? '', ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8'); }

The same escaping protects ordinary attribute values inside quotes, such as value, title and alt, <input value="<?= e($email) ?>">. Never print visitor data into an attribute that runs code, such as onclick, or into style, where escaping does not protect.

To hand a value to JavaScript, put json_encode($value, JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT | JSON_THROW_ON_ERROR) inside a script block, or put e($value) in a data- attribute and read it from the script.

In a URL, use rawurlencode for each part of the path and urlencode or http_build_query for query values, then print the whole address with e(). A link typed by a visitor must start with http:// or https:// after trimming, compared without regard to case, because javascript: addresses run code when clicked.

strip_tags is not a security function. Store the original text in the database and escape only when printing.
