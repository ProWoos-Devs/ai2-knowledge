Keeping secrets out of the code

Database passwords, API keys and mail passwords must never be written in a page, and never committed to git. Code is copied, shared and published, and public repositories are searched for passwords by automated tools.

Keep them in a configuration file outside the folder the web server serves. If the site is in /srv/site/public, put the file in /srv/site/config.php, one level up.

<?php
return [
    'db_user' => 'shop_app',
    'db_pass' => 'a long random password',
];

Load it where it is needed with $config = require __DIR__ . '/../config.php';. A file that returns an array keeps the values out of global variables. Because the file is outside the web folder, a browser cannot fetch it, even on a day when the server sends PHP files as plain text by mistake.

Let only the right users read it. sudo chown you:http /srv/site/config.php and chmod 640 lets you change it and the web server read it, and nobody else on the machine.

Add the file to .gitignore, and commit an example copy with the values blanked, config.example.php, so others know which settings are needed.

Environment variables are another common place for secrets. getenv('DB_PASS') reads one. Never print phpinfo() on a public page, because it lists them.

If a secret was ever committed or published, change it at once. Deleting it from the code does not remove it from the history or from copies already made.
