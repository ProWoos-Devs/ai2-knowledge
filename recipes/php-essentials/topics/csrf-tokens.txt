Forms that cannot be sent from another site, CSRF tokens

A logged-in visitor's browser sends their session cookie with every request to your site, even a request started by a page on another site. A hostile page can therefore submit a hidden form to your change-email or delete-account page, and it runs as that visitor. This is cross-site request forgery, CSRF.

The defense is a secret token that only your pages know. Make one per session. The session must be running first, so both the page with the form and the page that receives it call session_start() before any output, as the sessions topic shows.

if (empty($_SESSION['csrf'])) {
    $_SESSION['csrf'] = bin2hex(random_bytes(32));
}

Put it in every form that changes something.

<input type="hidden" name="csrf" value="<?= htmlspecialchars($_SESSION['csrf']) ?>">

Check it before doing anything with the request.

$sent = $_POST['csrf'] ?? '';
if (empty($_SESSION['csrf']) || !is_string($sent) || !hash_equals($_SESSION['csrf'], $sent)) {
    http_response_code(403);
    exit('This form has expired. Please reload the page and try again.');
}

The check must fail when the session has no token. Otherwise a forged form that sends no token compares an empty string with an empty string and passes. hash_equals compares in constant time, so the comparison does not leak the token one character at a time.

Rules that go with it. Never change data in answer to a GET request, so a link or an image cannot trigger a change. Set the session cookie with samesite Lax or Strict, which stops most cross-site requests in current browsers but is a second layer, not a replacement for the token. For JavaScript requests, send the same token in a header and check it the same way.

Frameworks such as Laravel and Symfony, and WordPress with its nonces, already do this. Use theirs when you work inside one.
