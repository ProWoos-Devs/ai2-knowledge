Accepting file uploads safely

An uploaded file is the most dangerous input a site takes. If someone can upload shell.php into a folder the web server runs, they control the site.

The form needs method="post" and enctype="multipart/form-data". The file arrives in $_FILES['photo'], with the temporary path in tmp_name, the error code in error and the size in size.

Check everything before keeping it.

Check isset($_FILES['photo']) first. If the whole form is larger than post_max_size, 8M in AI-2's php.ini, PHP gives no error code at all and $_POST and $_FILES are simply empty.
The error must be UPLOAD_ERR_OK. UPLOAD_ERR_INI_SIZE means the file was larger than upload_max_filesize, 2M in AI-2's php.ini.
Check the size yourself as well, with a limit that suits your site.
Decide the type from the file's content, never from its name or from the type the browser sent, which the visitor controls. (new finfo(FILEINFO_MIME_TYPE))->file($tmp) reads the content. Accept only a fixed list, such as image/jpeg and image/png.
Never keep the visitor's file name. Make your own, $name = bin2hex(random_bytes(16)) . '.jpg';, with the extension taken from your list for that type.
Move it and check that the move worked, if (!move_uploaded_file($tmp, $dir . '/' . $name)) { http_response_code(500); exit('The upload could not be saved.'); }. It refuses files that did not come from an upload, and fails when the folder is missing or the web server cannot write to it.

Store uploads outside the web folder and send them through a PHP script that sets the right Content-Type and the header X-Content-Type-Options: nosniff, so the browser does not guess another type. If they must sit inside the web folder, set the web server so that folder never runs PHP.

For images, getimagesize gives the width and height, or false, but a file that only starts like an image can pass it, so it does not prove the file is an image. Refuse false and very large dimensions before loading the image, because a small file can unpack into a huge picture. Then save a new copy with the gd extension, the separate package php-gd on AI-2, refuse the file if gd cannot read it, and keep only the new copy, which drops anything extra stored inside the original.
