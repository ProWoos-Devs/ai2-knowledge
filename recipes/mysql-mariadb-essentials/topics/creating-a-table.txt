Creating a table and choosing column types

A table is a list of columns, each with a name and a type.

CREATE TABLE customers (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255) NOT NULL UNIQUE,
  balance DECIMAL(10,2) NOT NULL DEFAULT 0,
  birthday DATE NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Choosing types.

Whole numbers. INT holds up to about two billion, or about four billion with UNSIGNED. BIGINT is for larger counts and ids. BOOLEAN is another name for TINYINT(1), a small number where 0 means false and 1 means true. It can still hold other small numbers, so a program should store only 0 and 1 in it.
Money and anything that must add up exactly. DECIMAL(10,2), ten digits with two after the point. Never FLOAT or DOUBLE, which store approximations, so sums of prices drift by fractions of a cent.
Short text. VARCHAR(n), where n is the most characters allowed. Long text. TEXT, up to 64 KB, or MEDIUMTEXT.
Dates. DATE for a day, DATETIME for a moment. Store moments in UTC and convert when showing them.

NOT NULL means the column must always have a value. DEFAULT gives the value used when an insert leaves the column out. UNIQUE refuses a second row with the same value, which also creates an index.

ENGINE=InnoDB is already the default on both servers and gives transactions and foreign keys. Saying it, and the character set, keeps the table the same on a server set up differently.

Check the result with DESCRIBE customers;.
