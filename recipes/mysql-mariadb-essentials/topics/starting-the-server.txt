Starting the database server on AI-2

Install the server and its runit service with sudo pacman -S mariadb mariadb-runit. The client, mariadb, comes with it.

Before the first start the data folder must be created. Run this once, and never again on a machine that already has data.

sudo mariadb-install-db --user=mysql --basedir=/usr --datadir=/var/lib/mysql

It also creates an account mysql@localhost for the system's mysql user. That is normal.

A new MariaDB listens on port 3306 on every network address. If only programs on this machine use it, the usual case, add the line bind-address = 127.0.0.1 under [mysqld] in /etc/my.cnf.d/server.cnf before starting it.

Then make the service start at every boot and start it now.

sudo artix-service enable mariadb
sudo sv up mariadb

sudo sv status mariadb says whether it is running. run followed by a number of seconds means it is up. down, or a run time that keeps resetting to a few seconds, means it is stopping or crashing.

On AI-2 the server writes no error log file. To see why it will not start, stop the service with sudo sv down mariadb and start the server by hand, sudo -u mysql mariadbd. It prints the reason in the terminal and stops. If it does start, press Ctrl+C and go back to sudo sv up mariadb. If it says /run/mysqld is missing, create it with sudo install -d -o mysql -g mysql /run/mysqld.

Restart after changing settings with sudo sv restart mariadb. AI-2 runs runit, so systemctl commands from other guides do not exist here.

After the first start, run sudo mariadb-secure-installation. The topic on keeping the database safe goes through it.

After an upgrade to a new MariaDB release, pacman prints a reminder that reads mariadb-upgrade -u root -p. On AI-2 run sudo mariadb-upgrade instead, since root logs in without a password.
