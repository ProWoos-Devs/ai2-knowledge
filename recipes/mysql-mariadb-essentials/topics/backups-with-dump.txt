Making a backup, mariadb-dump and mysqldump

A dump is a text file of SQL that recreates the tables and their rows. On AI-2 the program is mariadb-dump, and mysqldump starts the same one. On MySQL it is mysqldump -u root -p in place of sudo mariadb-dump.

The dump holds all your data, including customers' details and password hashes, so make the file private as it is written. Run umask 077 first in the same terminal, then the dump.

umask 077
sudo mariadb-dump --single-transaction --routines --events shop > shop-2026-11-17.sql

--single-transaction gives a consistent copy of InnoDB tables while the site keeps reading and writing, without locking them. Do not change the tables themselves during the dump, no ALTER, RENAME, DROP or TRUNCATE, and tables of other engines, such as MyISAM, are not covered by it. --routines adds stored procedures and functions and --events adds scheduled events, both left out otherwise. Triggers are included already.

A dump made this way has no CREATE DATABASE or USE line, so it can be loaded into a database of any name. --databases shop adds them, and --all-databases dumps every database. Such a dump always loads into the databases it names.

Compress it as it is written, since SQL text shrinks a lot. Write to a new name first and keep it only if every step worked, so a failed run does not replace the last good backup.

set -o pipefail
sudo mariadb-dump --single-transaction --routines --events shop | gzip > shop.new.sql.gz && gzip -t shop.new.sql.gz && mv shop.new.sql.gz shop.sql.gz

pipefail makes the line fail when the dump fails, not only when gzip does, and gzip -t checks the compressed file. A finished dump also ends with a line starting -- Dump completed, which zcat shop.sql.gz | tail -n 1 shows.

A dump of shop alone does not hold the database accounts. Save the output of sudo mariadb -e "SHOW CREATE USER 'shop_app'@'localhost'; SHOW GRANTS FOR 'shop_app'@'localhost';" with the backup and keep it as private, since it contains the password hash. On a new server, create the account first, then give the grants.

Keep backups on another disk or machine, and now and then load one into a throwaway server, as the topic on restoring shows. Copying /var/lib/mysql while the server runs does not make a usable backup.

For a nightly backup, put these commands in a small script and let cron run the script as root, which logs in through the same unix_socket as sudo mariadb. A % in a crontab line itself has to be written \%.
