A forgotten root password

On AI-2 with MariaDB this is rarely a problem. MariaDB's root account trusts the system's root user, so sudo mariadb logs in without the database password. From there, change any password with ALTER USER.

ALTER USER 'shop_app'@'localhost' IDENTIFIED BY 'new password';

Be careful with root itself. ALTER USER 'root'@'localhost' IDENTIFIED BY 'x'; replaces the sudo login with a password only. To keep both, write it this way.

ALTER USER 'root'@'localhost' IDENTIFIED VIA unix_socket OR mysql_native_password USING PASSWORD('new password');

If sudo mariadb no longer works because root's login was changed, start the server once without its permission checks.

sudo sv down mariadb
sudo -u mysql mariadbd --skip-grant-tables --skip-networking &
sudo mariadb

At that prompt, FLUSH PRIVILEGES; loads the permission tables again, which is needed before account changes work, then run the ALTER USER above. Leave with exit, stop the temporary server with sudo pkill -x mariadbd, and start the service again with sudo sv up mariadb.

While it runs that way anyone on the machine can log in as root with no password, which is why --skip-networking keeps the network out. Do not leave it running.

On MySQL the server program is mysqld and the root account uses a password. The MySQL manual's method writes ALTER USER 'root'@'localhost' IDENTIFIED BY 'new password'; into a file that only the mysql user can read, starts the server once with --init-file pointing at it, and deletes the file after the server is up.
