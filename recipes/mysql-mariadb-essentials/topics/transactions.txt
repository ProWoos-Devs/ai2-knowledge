Several changes that must all happen or none, transactions

Moving money from one account to another is two updates. If the second fails after the first succeeded, the money is gone. A transaction makes the two one unit.

START TRANSACTION;
UPDATE accounts SET balance = balance - 50 WHERE id = 1;
UPDATE accounts SET balance = balance + 50 WHERE id = 2;
COMMIT;

Until COMMIT, other connections do not see the changes. ROLLBACK; instead of COMMIT; undoes everything since START TRANSACTION. If the connection drops or the server stops before COMMIT, the changes are rolled back on their own.

Transactions work on InnoDB tables, the default on both servers. A MyISAM table ignores them, so check old tables with SHOW TABLE STATUS, whose Engine column says which.

Some statements end a transaction by themselves with an automatic commit, among them CREATE TABLE, ALTER TABLE, DROP TABLE and TRUNCATE. A schema change cannot be undone with ROLLBACK.

In PHP with PDO.

try {
    $pdo->beginTransaction();
    $pdo->prepare('UPDATE accounts SET balance = balance - ? WHERE id = ?')->execute([50, 1]);
    $pdo->prepare('UPDATE accounts SET balance = balance + ? WHERE id = ?')->execute([50, 2]);
    $pdo->commit();
} catch (Throwable $e) {
    $pdo->rollBack();
    throw $e;
}

Keep transactions short. While one is open, the rows it changed stay locked, and other connections that want them wait. Never wait for a person to click something in the middle of one.

Deadlock found when trying to get lock means two transactions each waited for the other. The server cancels one of them. Run that transaction again from the start.
