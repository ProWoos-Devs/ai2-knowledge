Logging in with the client, and Access denied

On AI-2, sudo mariadb opens the MariaDB prompt as the database's root user, with no password. That works because MariaDB's root account trusts the system's root user through the unix_socket method. Leave the prompt with exit.

To log in as another account, mariadb -u shop_app -p shop. -u names the user, -p makes the client ask for the password, and the last word is the database to open. Write nothing straight after -p, so the password is not saved in the shell history or shown to other users in the process list. On MySQL the same commands start with mysql.

ERROR 1698 (28000): Access denied for user 'root'@'localhost' means you ran mariadb -u root without sudo. Use sudo mariadb.

ERROR 1045 (28000): Access denied for user 'shop_app'@'localhost' (using password: YES) means the password is wrong for that user at that host, or the account does not exist. using password: NO means no password was sent, so you probably forgot -p.

An account in MySQL and MariaDB is a user name and a host together. 'shop_app'@'localhost' and 'shop_app'@'%' are two different accounts with their own passwords and rights. A program connecting over the network with host=127.0.0.1 may need its own account, because 127.0.0.1 is not the same host as localhost to the server.

As root, SELECT user, host, plugin FROM mysql.user; lists the accounts, and SHOW GRANTS FOR 'shop_app'@'localhost'; shows what one may do.
